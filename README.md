Модель базы данных и Pydantic-схемы разделены.

- `delete(book)` — удалить книгу.

Все методы асинхронные, работают через `AsyncSession`.

## Ответы на контрольные вопросы

1. **Что такое реляционная база данных?**
   База данных, в которой данные хранятся в виде связанных таблиц (отношений).

2. **Что такое таблица?**
   Набор строк (записей) с одинаковым набором столбцов (полей).

3. **Что такое первичный ключ?**
   Поле (или набор полей), однозначно идентифицирующее запись в таблице. В нашем проекте — `books.id`.

4. **Что такое внешний ключ?**
   Поле, ссылающееся на первичный ключ другой таблицы. Обеспечивает связь между таблицами. Понадобится в следующих лабораторных (например, `reader_id` в таблице выдач).

5. **Что такое ORM?**
   Object-Relational Mapping — технология, позволяющая работать с таблицами базы данных как с объектами языка программирования.

6. **Для чего нужна сессия базы данных?**
   Сессия — объект, через который выполняются запросы к базе, отслеживаются изменения объектов и управляются транзакции.

7. **Чем модель отличается от схемы?**
   Модель (SQLAlchemy) описывает структуру таблицы в базе данных. Схема (Pydantic) описывает формат входных и выходных данных API. Их разделяют, чтобы API и структура БД могли развиваться независимо.

## Ответы на контрольные вопросы

### 1. Что такое миграция базы данных?

Миграция — это файл, описывающий изменение структуры базы данных: создание, изменение или удаление таблиц и колонок. Она позволяет применять и откатывать изменения в контролируемом виде.

### 2. Зачем нужен Alembic?

Alembic предназначен для управления схемой базы данных через миграции в проектах на SQLAlchemy. Он позволяет синхронизировать структуру базы данных между разработчиками и различными окружениями.

### 3. Что делает команда `alembic upgrade head`?

Применяет все ещё не применённые миграции вплоть до самой последней версии (`head`). Приводит базу данных к актуальному состоянию.

### 4. Что делает команда `alembic downgrade`?

Откатывает миграции:

- `alembic downgrade -1` — откатывает одну последнюю миграцию.
- `alembic downgrade base` — откатывает все миграции до исходного состояния.

### 5. Почему нельзя вручную менять структуру базы данных?

При ручном изменении структуры фактическая схема базы данных перестаёт соответствовать истории миграций. Другие разработчики или серверы не смогут воспроизвести изменения, а выполнение следующей команды `alembic upgrade head` может привести к ошибкам.

Поэтому структуру базы данных следует изменять через Alembic, чтобы изменения были зафиксированы и могли быть воспроизведены в разных окружениях.

### 2. Добавление модели Автора
В файле `app/models/author.py` была создана модель:
```python
class Author(Base):
    __tablename__ = "authors"
```

```python
    batch_op.drop_column('author')
```

## Ответы на контрольные вопросы

1. **Что такое внешний ключ?**
   Это колонка (или набор колонок), которая ссылается на первичный ключ другой таблицы. Она используется для обеспечения ссылочной целостности и создания связей между таблицами (например, `author_id` в таблице `books`).
2. **Что такое связь «один ко многим»?**
   Это тип связи, при котором одной записи в таблице A (Автор) может соответствовать несколько записей в таблице B (Книги), но каждая запись в таблице B связана только с одной записью в таблице A.
3. **Что такое связь «многие ко многим»?**
   Связь, при которой записи в таблице A могут быть связаны с несколькими записями в таблице B, и наоборот. Реализуется через промежуточную (ассоциативную) таблицу.
4. **Что такое пагинация?**
   Это разбиение большого объема данных на логические страницы (например, по 10 или 20 записей). Реализуется с помощью параметров `limit` (размер страницы) и `offset` (смещение).
5. **Что такое фильтрация?**
   Это выборка данных, удовлетворяющих определенному условию (например, только книги жанра «Роман»). В SQL реализуется с помощью оператора `WHERE`.
6. **Что такое проблема N+1?**
   Это проблема производительности ORM, при которой для выборки основного списка выполняется 1 запрос, а затем для каждой связанной сущности (в цикле) выполняется еще N запросов. В итоге получается 1+N запросов к базе данных.
7. **Как можно уменьшить количество запросов к базе данных?**
   Использовать жадную (eager) загрузку связей, например, метод `selectinload` или `joinedload` в SQLAlchemy. Это позволяет выгрузить основную сущность и связанные с ней данные за 1-2 запроса.

## Ответы на контрольные вопросы

1. **Что такое аутентификация?**
   Это процесс проверки подлинности пользователя (подтверждение того, что он тот, за кого себя выдает). Обычно выполняется с помощью логина и пароля.
2. **Что такое авторизация?**
   Это процесс проверки прав доступа аутентифицированного пользователя к определенным ресурсам или действиям (например, может ли он удалять книги).
3. **Что такое JWT?**

5. **Что такое хэширование?**
   Это необратимое преобразование данных (пароля) в строку фиксированной длины с помощью математической функции (в нашем случае Bcrypt).
6. **Что означает статус `401`?**

7. **Что означает статус `403`?**
   `Forbidden` (Доступ запрещен) — клиент успешно аутентифицирован, но у него нет прав для выполнения этого действия (например, роль `user` пытается создать книгу).

1. **Что такое `UploadFile`?**
   Это специальный класс в FastAPI, предназначенный для приема файлов из HTML-форм (multipart/form-data). Он предоставляет удобный доступ к имени файла, заголовкам и самому содержимому (как к объекту файла Python).

   Это сильно раздувает размер базы данных, замедляет работу с ней (резервное копирование, индексация) и делает сложным раздачу файлов клиентам. Базы данных оптимизированы для текста и чисел, а не для больших бинарных объектов.

4. **Что такое фоновая задача?**
   Это операция, которая выполняется сервером асинхронно, *после* того как клиент уже получил HTTP-ответ. Клиенту не нужно ждать её завершения.

### 2. Изоляция тестовой базы данных (conftest.py)
Главное требование при написании тестов — они не должны ломать основную (рабочую) базу данных. Для этого в файле `tests/conftest.py` была настроена **изолированная тестовая база данных в оперативной памяти** (SQLite `:memory:`).

Была реализована функция `override_get_session`, которая подменяет основную зависимость `get_session` в FastAPI:
```python
fastapi_app.dependency_overrides[get_session] = override_get_session
```
Это гарантирует, что при выполнении тестов FastAPI будет обращаться к тестовой базе, которая создается перед запуском тестов и полностью уничтожается после их завершения. 

Также были написаны фикстуры (`client`, `admin_token`), которые автоматически создают асинхронный HTTP-клиент и регистрируют администратора для получения JWT-токена.

## Цель работы

Научиться разделять ответственность между слоями приложения (маршруты, сервисы, репозитории) и реализовать единый централизованный формат возврата ошибок.

---

## Ход выполнения работы

### 1. Создание единого формата ошибок
По умолчанию FastAPI возвращает ошибки в формате `{"detail": "..."}`. По требованиям методички мы привели все ошибки к единому стандарту:
```json
{
  "error": {
    "code": "http_error",
    "message": "Book not found",
    "details": {}
  }
}
```

Для этого был создан файл `app/core/exceptions.py`, содержащий два глобальных обработчика:
* `http_exception_handler` — перехватывает все ошибки HTTP (401, 403, 404, 400).
* `validation_exception_handler` — перехватывает ошибки валидации Pydantic (422).

Они были подключены к приложению в файле `app/main.py` с помощью `app.add_exception_handler(...)`.

### 2. Настройка логирования
В файле `app/core/logging.py` была настроена функция `setup_logging()`, которая использует стандартный модуль `logging` для вывода логов в консоль. Логирование было включено в `app/main.py`.

### 3. Вынос бизнес-логики в сервисный слой
Раньше бизнес-логика (проверка ролей, вызовы репозитория, обработка ошибок) находилась прямо в функциях маршрутов `app/api/v1/book.py`. Это нарушало принцип единственной ответственности.

Был создан слой **Сервисов**. В файле `app/services/book.py` реализован класс `BookService`:
* В конструктор класса внедряется `BookRepository`.
* В методах `create`, `update`, `delete` реализована проверка ролей пользователя (`admin`, `manager`). Если роль не подходит — выбрасывается исключение `403 Forbidden`.
* При успешном создании книги в лог пишется запись через `logger.info(...)`.

### 4. Внедрение зависимостей (DI)
В файле `app/api/deps.py` была добавлена функция `get_book_service` и аннотированный тип `BookServiceDep`. Теперь FastAPI сам создает репозиторий, передает его в сервис и внедряет сервис в маршруты.

### 5. "Тонкие" маршруты
Файл `app/api/v1/book.py` был переписан. Теперь маршруты не знают о базе данных (о репозиториях) и не содержат проверок ролей. Они просто принимают запрос, вызывают метод сервиса и возвращают результат:
```python
@router.post("/", response_model=BookRead, status_code=status.HTTP_201_CREATED)
async def create_book(data: BookCreate, service: BookServiceDep, current_user: CurrentUserDep) -> BookRead:
    return await service.create(data, current_user.role)
```

## Ответы на контрольные вопросы

1. **Что такое архитектура приложения?**
   Это структура организации кода, разделение его на модули и слои, а также правила их взаимодействия. Хорошая архитектура делает код понятным, тестируемым и удобным для доработки.
2. **Зачем разделять код на слои?**
   Чтобы разделить зоны ответственности. Если завтра мы решим сменить базу данных с SQLite на PostgreSQL, мы изменим только слой репозиториев, не трогая маршруты и бизнес-логику.
3. **Что такое бизнес-логика?**
   Это правила предметной области. Например: "создавать книгу может только администратор", "нельзя выдать книгу, если ее нет в наличии".
4. **Что такое репозиторий?**
   Это слой, который отвечает исключительно за доступ к данным (запросы к БД через SQLAlchemy). Он не содержит бизнес-правил.
5. **Что такое сервисный слой?**
   Это слой, в котором живет бизнес-логика. Сервис вызывает методы репозитория и применяет к полученным данным правила (например, проверяет права доступа).
6. **Что такое внедрение зависимостей?**
   Это паттерн, при котором объект (например, класс `BookService`) не создает свои зависимости (репозиторий) сам, а получает их извне (через конструктор). В FastAPI это реализуется через `Depends`.
