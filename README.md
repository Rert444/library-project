# Отчёт по лабораторной работе №2

## Цель работы

Научиться подключать базу данных к FastAPI-приложению и реализовывать операции создания, чтения, обновления и удаления с использованием SQLAlchemy.

## Ход выполнения работы

### 1. Структура проекта

Проект организован по слоям:

- `app/api/` — маршруты (эндпоинты);
- `app/core/` — конфигурация;
- `app/db/` — подключение к базе данных;
- `app/models/` — модели SQLAlchemy;
- `app/schemas/` — Pydantic-схемы;
- `app/repositories/` — слой доступа к данным;
- `app/main.py` — точка входа приложения.

### 2. Установка зависимостей

Установлены библиотеки FastAPI, Uvicorn, SQLAlchemy (с поддержкой asyncio), aiosqlite, pydantic-settings.

### 3. Настройка конфигурации

Создан файл `.env`, в котором заданы имя приложения, режим отладки и строка подключения к базе данных:

```
APP_NAME="Library API"
APP_DEBUG=true
DATABASE_URL=sqlite+aiosqlite:///./library.db
```

В файле `app/core/config.py` описан класс `Settings` на базе `pydantic-settings`, который читает переменные из `.env`. Файл `.env` добавлен в `.gitignore`.

### 4. Подключение базы данных

В файле `app/db/base.py` объявлен базовый класс `Base` (наследник `DeclarativeBase`).

В файле `app/db/session.py`:

- создан асинхронный движок `create_async_engine`;
- создана фабрика сессий `async_sessionmaker`;
- реализована зависимость `get_session()`, которая отдаёт сессию FastAPI и автоматически закрывает её после обработки запроса.

В качестве СУБД используется SQLite через драйвер `aiosqlite`.

### 5. Модель базы данных

В файле `app/models/book.py` описана модель `Book` для таблицы `books` со следующими колонками:

- `id` — первичный ключ;
- `title` — название книги;
- `author` — автор;
- `genre` — жанр;
- `year` — год издания;
- `description` — описание;
- `copies_total` — всего экземпляров;
- `copies_available` — доступно экземпляров;
- `created_at` — дата создания;
- `updated_at` — дата обновления.

На колонки `id`, `title`, `author` добавлены индексы. В файле `app/models/__init__.py` модель импортируется, чтобы она регистрировалась в `Base.metadata`.

### 6. Pydantic-схемы

В файле `app/schemas/book.py` описаны схемы:

- `BookBase` — общие поля с валидацией (`min_length`, `ge`, `le`);
- `BookCreate` — для входных данных при создании;
- `BookUpdate` — все поля опциональны, для частичного обновления;
- `BookRead` — для ответа клиенту: `BookBase` + `id` + `copies_available` + `created_at` + `updated_at`, с `from_attributes=True`.

Модель базы данных и Pydantic-схемы разделены.

### 7. Слой репозитория

В файле `app/repositories/book.py` создан класс `BookRepository` со следующими методами:

- `list()` — получить все книги;
- `get(book_id)` — получить книгу по идентификатору;
- `create(data)` — создать книгу; при этом `copies_available` выставляется равным `copies_total`;
- `update(book, data)` — частичное обновление; при изменении `copies_total` пересчитывается `copies_available` с учётом уже выданных экземпляров;
- `delete(book)` — удалить книгу.

Все методы асинхронные, работают через `AsyncSession`.

### 8. Зависимости FastAPI

В файле `app/api/deps.py` описаны:

- `SessionDep` — зависимость, отдающая `AsyncSession`;
- `get_book_repository()` — фабрика репозитория, получающая сессию через `Depends(get_session)`;
- `BookRepoDep` — зависимость для внедрения репозитория в маршруты.

### 9. CRUD-маршруты

В файле `app/api/v1/books.py` реализованы пять эндпоинтов:

| Метод | URL | Назначение | Код ответа |
|---|---|---|---|
| GET | `/api/v1/books/` | список книг | 200 |
| GET | `/api/v1/books/{book_id}` | книга по id | 200 / 404 |
| POST | `/api/v1/books/` | создать книгу | 201 |
| PUT | `/api/v1/books/{book_id}` | обновить книгу | 200 / 404 / 400 |
| DELETE | `/api/v1/books/{book_id}` | удалить книгу | 204 / 404 |

Во всех эндпоинтах используются Pydantic-схемы для входных и выходных данных. Возвращаются корректные статус-коды: `201` при создании, `204` при удалении, `404` при отсутствии объекта. Ошибка валидации `422` формируется FastAPI автоматически. Метод `PUT` обрабатывает `ValueError` из репозитория и возвращает `400` с понятным сообщением.

### 10. Точка входа

В файле `app/main.py`:

- создано приложение `FastAPI` с параметрами из настроек;
- реализован `lifespan`-контекст: при старте создаются таблицы (`Base.metadata.create_all`), при остановке закрывается движок (`engine.dispose()`);
- подключён роутер `books` через `APIRouter(prefix="/api/v1")`;
- добавлен служебный эндпоинт `GET /health`.

### 11. Отладка в процессе работы

В ходе выполнения возникли и были устранены следующие ошибки:

| Ошибка | Причина | Решение |
|---|---|---|
| `ImportError: cannot import name 'books'` | циклический импорт в `__init__.py` | импортировать `router` напрямую из `app.api.v1.books` |
| `NameError: asynccontextmanager` | не был импортирован из `contextlib` | добавлен импорт `from contextlib import asynccontextmanager` |
| `NameError: APIRouter` | не был импортирован из `fastapi` | добавлен импорт `from fastapi import APIRouter, FastAPI` |
| `ModuleNotFoundError: app.api.v1.books` | файл назывался `book.py` вместо `books.py` | файл переименован |
| `500 Internal Server Error` при POST | путь был `""` вместо `"/"`, FastAPI делал `307`-редирект и терял тело POST | заменено `@router.post("")` на `@router.post("/")`, то же для `GET` |

Для диагностики использовался запуск приложения через `httpx.ASGITransport(app=app)` — это позволяло воспроизвести HTTP-запрос в том же процессе, минуя Uvicorn.

### 12. Проверка работоспособности

Создание книги через `POST /api/v1/books/` возвращает `201 Created` с телом:

```json
{
  "id": 2,
  "title": "Мастер и Маргарита",
  "author": "Михаил Булгаков",
  "genre": "Роман",
  "year": 1967,
  "description": "Классика",
  "copies_total": 3,
  "copies_available": 3,
  "created_at": "2026-10-10T18:13:44",
  "updated_at": "2026-10-10T18:13:44"
}
```

- Данные сохраняются между перезапусками Uvicorn благодаря файлу `library.db`.
- Документация `/docs` доступна и содержит раздел `books` со всеми пятью эндпоинтами.
- При невалидных данных возвращается `422`, при обращении к несуществующей книге — `404`.

## Ответы на контрольные вопросы

1. **Что такое реляционная база данных?**
   База данных, в которой данные хранятся в виде связанных таблиц (отношений).

2. **Что такое таблица?**
   Набор строк (записей) с одинаковым набором столбцов (полей).

3. **Что такое первичный ключ?**
   Поле (или набор полей), однозначно идентифицирующее запись в таблице. В нашем проекте — `books.id`.

4. **Что такое внешний ключ?**
   Поле, ссылающееся на первичный ключ другой таблицы. Обеспечивает связь между таблицами. Понадобится в следующих лабораторных (например, `reader_id` в таблице выдач).

5. **Что такое ORM?**
   Object-Relational Mapping — технология, позволяющая работать с таблицами базы данных как с объектами языка программирования.

6. **Для чего нужна сессия базы данных?**
   Сессия — объект, через который выполняются запросы к базе, отслеживаются изменения объектов и управляются транзакции.

7. **Чем модель отличается от схемы?**
   Модель (SQLAlchemy) описывает структуру таблицы в базе данных. Схема (Pydantic) описывает формат входных и выходных данных API. Их разделяют, чтобы API и структура БД могли развиваться независимо.
